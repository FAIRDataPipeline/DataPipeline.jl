Tracing provenance

What the pipeline records of every run - the code at its commit, what it read and what it wrote - is there to be asked. This page is what the package asks of it: what the registry knows about a file, where a file came from, what was made from it, how one version supersedes another, and the crate that packs the files of a paper with the provenance of each. None of it needs a token, so it all works outside fair run, against the local registry or a remote one.

Asking what the registry knows about a file or a repository

DataPipeline.identify takes a file, or a git repository by the path of its top-level folder, and asks the registry the FAIR CLI is configured to use, or any other, what it knows about it. No token is needed, so it works outside fair run:

DataPipeline.identify("results.csv")                     # the local registry
DataPipeline.identify("results.csv", remote = "origin")  # a remote of this project
DataPipeline.identify("results.csv", superseded = true)  # and the inputs behind it since superseded
DataPipeline.identify(repo = ".")                        # this checkout's commit and its ancestors
DataPipeline.identify(repo = ".", commits = "v0.55.0")   # one commit, by tag, branch, hash or release
# every run of this repository, including those made with uncommitted changes
DataPipeline.identify(repo = ".", commits = DataPipeline.AllCommits(dirty = true))
# a repository with no clone, by the registry's record of it alone
DataPipeline.identify(repo = "https://github.com/FAIRDataPipeline/DataPipeline.jl")

A file's identification carries the issues raised on it and, behind it, the issues raised on anything a run on the way read, or on a run's own code, config or script, each with the run it reaches the file through; with superseded = true it lists the inputs behind the file that a newer version of has been registered since, as outdated rather than wrong.

Ask a registry what it knows about a file, or about a git repository, on disk.

For a file, return a FileIdentification: the data products it is registered as, where the registry expects to find it, whether a newer version of any of those data products exists, the issues raised against it, and the issues raised on anything behind it - the inputs read on the way to it, at the versions read, and the code, config and script of the runs on the way - each with the run it reaches the file through. With superseded = true, the inputs read on the way that a newer version of has been registered since are reported too, as outdated rather than wrong. isempty(result.objects) means the registry has no record of a file with these contents. The file is identified by the SHA-1 of its contents, as everything in the pipeline is, so a copy under another name is recognised and an edited file is not.

For a git repository, named by the path of its top-level folder as repo, return a RepositoryIdentification: the code runs made from its commits, with their outputs, and any issues raised against those commits. The repository is known to the registry by the URL of its git remote - the one named by git.remote in its .fair/cli-config.yaml, else origin - and commits chooses which of its commits to report. Runs made with uncommitted changes are included only when commits is given dirty = true. When the checkout itself has uncommitted changes, AncestorCommits and CheckedOutCommit warn and use its commit as committed.

Arguments

  • path::String: the file to ask about.
  • repo: the git repository to ask about: the top-level folder of a clone, or the URL of its remote, which asks the registry's record alone. Any other folder is an ArgumentError, including one inside a repository.
  • registry::RegistryEndpoint: the registry to ask, which needs no token, e.g. RegistryEndpoint("http://127.0.0.1:8000/api/"); a DataRegistryHandle may be given instead, and its registry is used.
  • remote: with no registry given, the registry is the CLI's local registry, or the remote registry of that name in the current project's CLI configuration; see RegistryEndpoint.
  • superseded: for a file, whether to report the inputs behind it that have been superseded.
  • commits: for a repository, AncestorCommits() (the default with a clone), CheckedOutCommit(), AllCommits() (the default by URL) or a commit by name - a tag, a branch, a commit hash or the version of a registered release of the code, as a string or as NamedCommit - each optionally with dirty = true. By URL there is no clone, so the checked-out commit and its ancestors are an ArgumentError, and a name resolves only as a full hash or a registered release.

DataPipeline.FileIdentification — Type
FileIdentification

What a registry knows about one file on disk, as returned by identify. objects is empty when the registry has never been told about a file with these contents.

Fields

  • path: the file asked about
  • hash: its SHA-1, which is how the registry identifies it
  • objects: the RegisteredObjects registered with that hash
  • provenance: the Trace back from every data product the file is registered as, or nothing for a file the registry does not know
  • upstream: every UpstreamIssue the trace finds, nearest the file first
  • outdated: every OutdatedInput the trace finds, when asked for with superseded = true, else nothing

DataPipeline.RegisteredObject — Type
RegisteredObject

One registry object a file is registered as: its description, where the registry expects to find it, what data products it serves and what problems are recorded against it. An object with no data products is one of a code run's own files - a working config, a submission script or a repository.

Fields

  • description: the object's description
  • url: the object's URL in the registry
  • root: the storage root the file is registered under
  • local_root: whether that root is on this machine
  • stored_path: the file's path within that root
  • data_products: the DataProductRecords it serves, if any
  • issues: the IssueRecords against it and its components

DataPipeline.UpstreamIssue — Type
UpstreamIssue

An issue identify found behind a file: raised on something a run on the way to the file read, at the version it read, or on a run's own code repository, working config or submission script.

Fields

  • issue: the TraceIssue
  • on: the TraceTarget of the issue that lies upstream of the file
  • through: the TraceRun it reaches the file through - the run that read the thing, or whose own file it is

  • input: true when the thing is a data product the run read, false when it is the run's repository, config or script

OutdatedInput

DataPipeline.IssueRecord — Type
IssueRecord

A problem recorded against something a file is registered as.

Fields

  • severity: how bad it is, as the registry holds it (larger is worse)
  • description: what the problem is
  • component: the name of the object component it was raised against, or nothing when raised against the file as a whole
  • url: its registry URL
  • uuid: its uuid

An IssueRecord names the issue to downstream, as its issue.

DataPipeline.RepositoryIdentification — Type
RepositoryIdentification

What a registry knows about a git repository, as returned by identify. commits is empty when no run was made from any of the commits selected.

Fields

  • path: the repository's top-level folder, or its URL when it was named by that alone
  • remote: the URL of the git remote the registry knows it by
  • head: the checked-out commit, or nothing with no clone
  • dirty: whether the working tree has uncommitted changes to tracked files; false with no clone
  • selection: the AbstractCommitSelection asked for
  • commits: the RegisteredCommits selected, newest commit first; those the local clone does not have come last, newest first by their earliest run

DataPipeline.AbstractCommitSelection — Type
AbstractCommitSelection

Which commits of a git repository identify reports, and whether it includes the runs made from them with uncommitted changes, which the registry records as <sha>-dirty: AncestorCommits, CheckedOutCommit or AllCommits. Each has a dirty field saying which, set by its constructor's dirty keyword.

AncestorCommits(; dirty = false)

Select the checked-out commit and every commit it descends from - the code the checkout grew from - and, if dirty, the runs made from them with uncommitted changes too. What identify reports for a repository unless told otherwise.

DataPipeline.AllCommits — Type
AllCommits(; dirty = false)

Select every commit of the repository that the registry holds runs for, whether or not the local clone has it, and, if dirty, the runs made from them with uncommitted changes too.

DataPipeline.NamedCommit — Type
NamedCommit(name; dirty = false)

Select one commit by name: a full commit hash, as it is; a tag, a branch or an abbreviated hash, resolved by the local clone; or the version of a release of the code that the registry holds, with or without a leading v, which resolves with no clone at all. A String given as commits means this. If dirty, the runs made from the commit with uncommitted changes too.

Where a file came from

DataPipeline.provenance traces a data product back: the run that made it, what that run read, the runs that made those, and so on to the data registered from elsewhere, each with its source. It takes a file, or a data product named namespace:name@version as the pipeline names one, and prints as a tree, newest first, each data product once:

DataPipeline.provenance("figures/summary.pdf")
DataPipeline.provenance("testing:SEIRS_model/report/julia@v0.0.1")
DataPipeline.provenance("testing:SEIRS_model/report/julia", depth = 2)   # two runs back
Provenance of testing:SEIRS_model/report/julia@v0.0.1  sha1 c896cfb9
<- run a1b118f0 on 2026-10-15 11:33, github.com/FAIRDataPipeline/DataPipeline.jl.git at 34d3bdca
   used testing:SEIRS_model/summary/julia@v0.0.1  sha1 b6ae4389
       issue, severity 3: an issue over an input and an output
   <- run 577160a1 on 2026-10-15 11:33, github.com/FAIRDataPipeline/DataPipeline.jl.git at 34d3bdca
      used PSU:SEIRS_model/parameters@v1.0.0  sha1 6294a595  superseded by v1.0.1  from https://doi.org/10.1038/s41592-020-0856-2 (supplement)
          issue, severity 2: an issue on the parameters
      used testing:SEIRS_model/results/model_output/julia@v0.0.1  sha1 e8912ec2
      <- run c30fbbdd on 2026-10-15 11:33, github.com/FAIRDataPipeline/DataPipeline.jl.git at 34d3bdca
         used PSU:SEIRS_model/parameters@v1.0.0  (above)

The value holds more than the tree prints - every data product, run and issue reached, keyed by registry URL - for a script to work over.

provenance(x; remote = nothing, depth = nothing)

Trace where a data product came from: the run that made it, what that run read, the runs that made those, and so on back to the data products that no run made, each with its source. Return a Trace{Upstream}, which prints as a tree, and holds every data product, run and issue reached, keyed by registry URL.

x names the data product: a file, whose contents identify it as identify does, every data product it is registered as being a root of the trace; or namespace:name@version, as the pipeline names one, with namespace:name meaning its newest version. The registry is the one the FAIR CLI is configured to use, or the project's remote named by remote, or registry, or the one handle was opened on; no token is needed.

depth is how many runs back along any path to go. By default the trace goes to the end of every path, and a data product that no run made is a root; with depth given, a data product at that depth that a run made is marked beyond, and the tree says so.

Every data product's line says whether a newer version of its name has been registered since, and the issues raised on it; an issue raised on several things is one issue, with each of them among its targets.

source
DataPipeline.Trace — Type
Trace{D <: AbstractTraceDirection}

What provenance and downstream return: the data products, runs and issues reached from one or more data products in one direction, D, each kept once by its registry URL. Printed as a tree from the roots.

Fields

  • registry: the RegistryEndpoint it was read from
  • roots: the registry URLs of the data products it starts from
  • products: every TraceProduct reached, by URL
  • runs: every TraceRun reached, by URL
  • issues: every TraceIssue raised on any of them, by URL
  • depth: the number of runs along any path it was cut at, or nothing for a trace that reaches the end of every path
source
DataPipeline.TraceProduct — Type
TraceProduct

One version of a data product in a Trace.

Fields

  • url: its registry URL, the key it has in the trace
  • namespace, name, version: what names it
  • hash: the SHA-1 of its file, or nothing for a data product with no file
  • location: where the registry says the file is, or nothing
  • description: its description, or nothing
  • format: the extension of its file type, as txt, or nothing
  • source: its TraceSource, or nothing when it has none
  • superseded_by: the highest version of its name in its namespace, when that is a newer one, else nothing
  • made_by: the registry URL of the run in the trace that made it, or nothing when the trace holds none
  • beyond: true when the trace was cut at this data product by its depth: a run that made it, going upstream, or that read it, going downstream, is not held
  • issues: the registry URLs of the issues raised on it or its components
source
DataPipeline.TraceRun — Type
TraceRun

A code run in a Trace.

Fields

  • url: its registry URL, the key it has in the trace
  • uuid: its uuid
  • date: when it started
  • description: its description
  • repository: the URL of the code repository it ran from, or nothing
  • commit: the commit it ran at, <sha>-dirty for a working tree with uncommitted changes, or nothing
  • config: where the registry says its working config is, or nothing
  • script: where the registry says its submission script is, or nothing
  • inputs: the registry URLs of the data products it read that the trace holds
  • outputs: the registry URLs of the data products it wrote that the trace holds
  • objects: the registry URLs of the objects that stand for its repository, config and script, those it has, which an issue on any of them names
  • issues: the registry URLs of the issues raised on its repository, config or script

  • component: the named component the issue is on, or nothing for the whole thing

What was made from a file

DataPipeline.downstream traces the other way: the runs that read a data product, what they wrote, the runs that read those, and on to the end of every path. It answers "I have found a problem in this - what must be made again?": every data product reached that no newer version has superseded. It starts from a data product, from everything the runs of a repository wrote, or from everything an issue is raised on, and prints as the mirror image of provenance:

DataPipeline.downstream("PSU:SEIRS_model/parameters@v1.0.0")
DataPipeline.downstream(repo = ".", commits = "v0.55.0")   # what this release's runs made, and on
DataPipeline.downstream(issue = 12)                        # what an issue affects
DataPipeline.downstream — Function
downstream(x; remote = nothing, depth = nothing)
downstream(registry, x; depth = nothing)
downstream(handle, x; depth = nothing)
downstream(; repo, remote = nothing, commits = nothing, depth = nothing)
downstream(registry; repo, commits = nothing, depth = nothing)
downstream(handle; repo, commits = nothing, depth = nothing)
downstream(; issue, remote = nothing, depth = nothing)
downstream(registry; issue, depth = nothing)
downstream(handle; issue, depth = nothing)

Trace what was made from a data product: the runs that read it, what they wrote, the runs that read those, and so on to the end of every path. Return a Trace{Downstream}, which prints as a tree, and holds every data product, run and issue reached, keyed by registry URL. What must be made again, now that a problem is known in the start, is every data product reached that no newer version has superseded.

x names the start: a file, whose contents identify it as identify does, every data product it is registered as being a root; or namespace:name@version, as the pipeline names one, with namespace:name meaning its newest version. With repo, the start is everything the runs of a git repository wrote: the repository and commits are as identify takes them, by the folder of a clone or the URL of its remote. With issue, the start is everything the issue is raised on - each data product, at the version it is on, and everything the runs made whose code repository, working config or submission script it is on - so that what the problem affects is what the trace holds. The issue is a TraceIssue or an IssueRecord from a trace or identify, its uuid, its registry URL, or the number the registry's own pages show it by. The registry is the one the FAIR CLI is configured to use, or the project's remote named by remote, or registry, or the one handle was opened on; no token is needed.

depth is how many runs forward along any path to go. By default the trace goes to the end of every path; with depth given, a data product at that depth that a run read is marked beyond, and the tree says so. Every data product's line says whether a newer version of its name has been registered since, and the issues raised on it.

Superseding a version

Data is often not wrong but out of date: a dataset is updated, and what was made from the old version is worth making again, though the old version was right in its day. supersede = true on a write says so. Once the new version is registered, an issue reading Superseded by namespace:name@vX.Y.Z is raised on the version before it, at severity 0, the lowest, so that identify of anything made from the old version reports it, and downstream of the old version is what to make again:

link_write!(handle, "era5/t2m/2021", path = "cache/era5_t2m_2021.nc", doi = era5,
            primary = false, supersede = true)

Where there is nothing to supersede - the file is the highest version's and unchanged, or the name has no version before - nothing is raised and an info message says so.

The crate for a paper

DataPipeline.crate fetches the RO-Crate the registry builds for data products: a package of their files with the provenance of each, in which every run with its code at its commit, everything it read, and each data product with its source and its issues travel together. The paper's figures in one folder is the case in mind:

DataPipeline.crate("figures")                            # the metadata, parsed
DataPipeline.crate("figures", to = "paper.zip")          # the zip, files packed
DataPipeline.crate("paper", strict = false)              # the sources left out, and said
DataPipeline.crate — Function
crate(paths...; remote = nothing, depth = 100, level = nothing,
      pack = nothing, to = nothing, strict = true)
crate(registry, paths...; depth = 100, level = nothing, pack = nothing,
      to = nothing, strict = true)
crate(handle, paths...; depth = 100, level = nothing, pack = nothing,
      to = nothing, strict = true)

Fetch the RO-Crate the registry builds for data products: a package of their files with the provenance of each, as a crate's metadata describes it, in which every run with its code at its commit, everything it read, each data product with its source and its issues travel together.

Each of paths is a file, a folder, or a data product named namespace:name@version (namespace:name for its newest version). A file is identified by its contents, as identify identifies one, and every data product it is registered as is a root of the crate; a folder means every file under it, the paper's figures in one folder being the case in mind. Files and folders whose names begin with a dot are left out and reported. A file the registry does not know is an error; with strict = false such files are left out and reported, so that a folder may hold the paper's sources beside its figures.

depth is how many runs back the crate goes along any path, 100 by default. level and pack are the registry's: level 1 or 2, what travels with each file, and pack one of "none", "roots", "supplements" and "all", whose bytes a zip holds; left out, the registry's defaults apply.

Without to, return the crate's metadata, its ro-crate-metadata.json, parsed: a dictionary with "@context" and "@graph". With to, a path ending in .zip, save the crate there as that zip, the metadata and the files pack chooses, and return the path; a path ending in .json saves the metadata there. The registry is the one the FAIR CLI is configured to use, or the project's remote named by remote, or registry, or the one handle was opened on; no token is needed.
